# Handbook site generation

## When to use

Use this skill when a task changes published content or its generated
artifacts:

- Adding, renaming, or removing an article in `articles/`.
- Changing an article title, description, language, or date.
- Adding or reordering an entry in `index.html`.
- Regenerating `feeds/articles.xml` or `sitemap.xml`.
- Debugging a mismatch reported by `t/integrity.t` or
  `t/reproducible.t`.

For prose review only, use `security-article-review`. For final checks, use
`content-publishing-validation`.

## Source and derived files

Article HTML is hand-authored and is the source for feed metadata. There is no
Markdown source for site content and no site generator.

| File | How it is maintained |
| --- | --- |
| `articles/*.html` | Hand-authored source. |
| `index.html` | Hand-curated; `scripts/update-articles.pl` can insert one list item. |
| `data/articles.json` | Hand-maintained index, not generated. |
| `feeds/articles.xml` | Generated by `scripts/rebuild-feeds.pl`. |
| `sitemap.xml` | Generated by `scripts/rebuild-sitemap.pl`. |
| `archive/*` | Produced and signed by CI; never edit. |
| `README.md`, `CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, `docs/`, `.github/` | Versioned maintainer material; excluded from the public tar and server sync, not from Git. |

`templates/articles.html` is a manual reference. It is not read by any script
and its `<head>` lacks the current canonical, description, and OpenGraph
metadata used by published articles. Do not treat it as a renderer or copy it
without adding the required metadata.

The archive and OpenBSD sync omit a maintained set of repository-only
documentation, VCS metadata, agent instructions, tooling configuration, tests,
and caches. Keep generated feeds, article metadata, images, and normal public
assets eligible for publication. Do not use a blanket `.md` or hidden-file
exclusion.

## Procedure

1. **Check the baseline.** Run `git status --short` and `git diff`. Preserve
   unrelated changes.
2. **Create or edit the article HTML.** Keep the existing document skeleton:
   `<!DOCTYPE html>`, `<html lang="en">`, viewport, title prefixed with
   `T.C.H. - `, local favicon and stylesheet, RSS alternate link, description,
   canonical URL, OpenGraph tags, skip link, site header/nav, main/article,
   article header, TOC where appropriate, and site footer.
3. **Add images fluidly.** Use local assets, keep intrinsic dimensions in the
   file, and rely on `max-width: 100%` with `height: auto`. Never add fixed
   `width`/`height` attributes or fixed pixel CSS widths.
4. **Fill the article header.** Use `<p class="kicker">`, one `<h1>`, a
   `<p class="meta">` containing the byline and `<time datetime="YYYY-MM-DD">`,
   and a `<p class="lede">`. Add the TL;DR section when the article needs it.
   The `<time>` value is the last-modified date used by the feed.
5. **Update `data/articles.json` manually.** Add or revise the slug entry with:
   - `en` (and optional `es`) pointing to the filename in `articles/`;
   - `pubdate` in `YYYY-MM-DD`, meaning first publication;
   - `title_en` (and optional `title_es`) exactly matching the page `<h1>`.
   Do not use `pubdate` for the last-modified value.
6. **Update `index.html`.** Add the link under the correct column, subsection,
   and `ul.article-list`. You may run `perl scripts/update-articles.pl`
   interactively. It writes only `index.html`, validates the subsection format,
   refuses an exact duplicate href, and does not check that the article file
   exists.
7. **Regenerate feeds.** Run `perl scripts/rebuild-feeds.pl` from the
   repository root. Do not use `--base-url` for committed feeds: the committed
   feed and GUIDs must remain root-relative so the same feed works on HTTPS,
   Tor, and I2P mirrors.
8. **Regenerate the sitemap.** Run `perl scripts/rebuild-sitemap.pl`.
9. **Inspect the generated diff.** Confirm that the new item appears once, in
   date-descending order, with the expected title and description, and that
   the sitemap includes the article URL.
10. **Run the tests.** `prove t` is offline and uses isolated fixtures for the
    mutating scripts. Fix metadata or regeneration drift before continuing.

## How the generators behave

### `scripts/rebuild-feeds.pl`

- Scans recursively for `articles/**/*.html` and ignores `index.html`.
- Reads language from the first `<html lang="...">`; any `es*` value selects
  the Spanish feed, otherwise English.
- Reads the title from the first `<h1>` or `<h2>` inside
  `header#article-header`, falling back to the whole document.
- Reads the description from `<meta name="description">`, then
  `p.lede`, then the first `<p>` in the header scope; it strips tags, collapses
  whitespace, and truncates to 420 characters.
- Reads the date from the first `<time datetime="...">`. It accepts
  `YYYY-MM-DD`, `YYYY-MM-DDTHH:MM:SS`, and space-separated timestamps, with an
  optional `Z` or `±HH:MM` offset. Date-only becomes midnight UTC. If no valid
  value exists, it falls back to the file modification time.
- Sorts by date descending, then slug ascending.
- Uses the basename as the slug. A nested article in a subdirectory is
  published at the root article URL for its basename, so duplicate basenames
  collide.
- Rewrites the entire RSS file. It preserves only the existing channel title,
  link, and description; other channel metadata is discarded.
- Emits root-relative item links and `guid isPermaLink="false"` values by
  default.
- If a blog feed file exists in `feeds/`, it takes precedence over the articles
  feed for the English target.

### `scripts/rebuild-sitemap.pl`

- Scans public `*.html` files under the repository root.
- Excludes paths containing `/archive/` or `/templates/`, and prunes the
  generated directories `.git`, `node_modules`, `dist`, `build`, `.cache`, and
  `tmp`.
- Maps `index.html` to `https://handbook.uhden.dev/` and a nested
  `<subdirectory>/index.html` to `https://handbook.uhden.dev/<subdirectory>/`.
- Emits only `<loc>` entries, sorted lexicographically, with no `lastmod`,
  `changefreq`, or `priority`.
- Uses a hard-coded site origin; do not change it for a mirror.

The validator's dprint step may resolve its npm plugins over the network even
when link checking is offline. Missing plugin downloads are reported and
skipped in check mode.

### Interactive helpers

- `perl scripts/update-articles.pl` asks for subsection, title, and slug and
  inserts one link into `index.html`. It does not create the article, update
  `data/articles.json`, or regenerate feeds.
- `perl scripts/update-feeds.pl [--replace] [ARTICLE]` asks for feed and
  article metadata. If `ARTICLE` is supplied, its `<time datetime>` value
  supplies the date; a missing path or unknown option is rejected. When
  `scripts/rebuild-feeds.pl` is executable, it automatically runs it and the
  prompted title/description are normally replaced by values parsed from the
  article HTML. Prefer editing the article and running `rebuild-feeds.pl`
  directly.

## Validation

- `prove t` passes, especially `t/integrity.t` and `t/reproducible.t`.
- Every `articles/*.html` appears in `data/articles.json`; every JSON entry
  points to an existing file and matches the `<h1>`.
- Every feed item points to an existing article and every GUID starts with
  `/articles/`.
- `feeds/` and `sitemap.xml` are byte-identical to fresh generator output.
- `git diff --stat` shows only intended source and generated changes.
- `git diff --check` reports no whitespace errors.
- Run `perl scripts/validate-website.pl --check-all` when the required tools
  are available; it includes formatting, internal links, `prove`, and
  optional linters.

## Common problems

- **Stale generated files.** Editing an article without rebuilding leaves the
  feed and sitemap behind; `t/reproducible.t` fails.
- **Absolute feed URLs.** Committing `--base-url` output fails
  `t/integrity.t`. Regenerate without the flag.
- **Missing `<time>`.** The feed falls back to file mtime; a fresh clone can
  then produce different bytes and fail reproducibility.
- **Nested article paths.** The feed flattens nested files to their basename.
  Avoid duplicate basenames.
- **Title drift.** A title changed in HTML but not in `data/articles.json`
  fails `t/integrity.t`.
- **Missing JSON entry.** A new article that is not listed fails the reverse
  coverage check.
- **Wrong index section.** `update-articles.pl` inserts only where the named
  nested section and `ul.article-list` exist.
- **Interactive feed insertion.** The automatic rebuild can overwrite the
  values you just entered; inspect the resulting feed.
- **Accidental formatting.** Running bare `validate-website.pl` applies
  formatting to source and generated files.

## Maintenance & Continuous Learning

Whenever this skill is used to change the repository, review this skill after
the implementation. Correct procedures that proved wrong, update commands,
paths, configuration and examples, incorporate reusable findings, and remove
outdated assumptions. Review the applicable root and nested `AGENTS.md` files,
specialized agents and related skills; update only the knowledge affected by
the work. Validate local references and run
`python3 scripts/validate-agent-knowledge.py --scope worktree` plus the
applicable project checks. For pull request comparisons, use the documented
`--scope range --base BASE_REF --head HEAD_REF` command. The canonical validator
is read-only and is required even when a task restricts execution of project
scripts; this does not authorize running installers or changing the host.
Report checks actually performed. A structural pass does not prove semantic
relevance, and a task is incomplete until synchronization is validated.
