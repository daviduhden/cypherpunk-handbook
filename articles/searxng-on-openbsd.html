Self-hosting SearXNG on OpenBSD over a Tor onion service

Written by FlyWithMe (a SimpleX Chat user) - Updated August 16, 2026

This guide shows how to self-host SearXNG on OpenBSD and expose it through a Tor onion service while keeping privileges separated and permissions minimal.

TL;DR

  • Create a dedicated _searxng user before installing dependencies.
  • Install and run SearXNG inside a Python virtual environment, store a separate settings.yml in /home/searxng, and optionally force all outbound traffic through Tor.
  • Bind Gunicorn to localhost and publish the service via a Tor v3 onion service to avoid exposing SearXNG directly on clearnet.

Context

This guide builds on an older tumfatig.net guide and adapts the installation to OpenBSD. SearXNG changes rapidly, while its official installation documentation targets Linux and recommends either the container image or the project installation script. The manual procedure below was tested on OpenBSD 7.9. Read the upstream migration notes before applying it to a later SearXNG release.

Preliminary steps

Set up a dedicated user

$ nano /etc/login.conf.d/searxng

searxng:\
        :openfiles=4096:\
        :tc=daemon:
$ useradd -g =uid -c "SearXNG metasearch engine" \
  -L searxng -s /sbin/nologin -d /home/searxng   \
  -m -r 2000..2500 _searxng

Installation

Install minimum system dependencies

$ pkg_add git python libxslt

Install SearXNG sources and prepare the environment

$ doas -u _searxng /bin/ksh -c 'cd /home/searxng && exec /bin/ksh -l'
$ echo "umask 077" >> ~/.profile
$ git clone https://github.com/searxng/searxng ~/src
$ python3 -m venv ~/pyenv
$ echo ". ~/pyenv/bin/activate" >> ~/.profile
$ ^D

Install SearXNG in the virtual environment

If you want, use torsocks with each git clone/git pull and pip command to fetch packages through Tor.

$ doas -u _searxng /bin/ksh -c 'cd /home/searxng && exec /bin/ksh -l'
$ command -v python && python --version

/home/searxng/pyenv/bin/python
Python 3.13.13
$ python -m pip install --upgrade pip setuptools wheel
$ cd ~/src
$ python -m pip install --use-pep517 --no-build-isolation --editable .

Configuration

This setup keeps the configuration file outside the source tree so source updates do not overwrite it.

$ doas -u _searxng /bin/ksh -c 'cd /home/searxng && exec /bin/ksh -l'
$ cp ~/src/searx/settings.yml ~/settings.yml
$ sed -i -e "s/ultrasecretkey/$(openssl rand -hex 32)/g" ~/settings.yml
$ chmod 0600 ~/settings.yml
$ echo 'export SEARXNG_SETTINGS_PATH=/home/searxng/settings.yml' >> ~/.profile

Tor proxy defaults in shell profile

To route network clients that honor standard proxy environment variables through Tor, add the following to ~/.profile. This covers tools such as Git and pip without placing torsocks before every command.

export ALL_PROXY='socks5h://127.0.0.1:9050'
export HTTP_PROXY="$ALL_PROXY" HTTPS_PROXY="$ALL_PROXY"

Configure SearXNG itself in ~/settings.yml, inside the outgoing section. This explicitly routes requests to search engines through the local Tor SOCKS proxy:

outgoing:
  request_timeout: 10.0
  max_request_timeout: 30.0
  pool_connections: 200
  retries: 2
  extra_proxy_timeout: 30
  using_tor_proxy: true
  proxies:
    all://:
      - socks5h://127.0.0.1:9050
$ . ~/.profile
$ nano ~/settings.yml

Run a local smoke test from the source directory (use torsocks if you did not configure ~/.profile as shown above):

$ cd ~/src
$ python searx/webapp.py
...
 * Serving Flask app 'webapp'
 * Debug mode: off
^C

Tor onion service configuration

To expose SearXNG through an onion address, add this to /etc/tor/torrc:

$ nano /etc/tor/torrc

HiddenServiceDir /var/tor/searx_hidden_service/
HiddenServiceVersion 3
HiddenServicePort 80 127.0.0.1:8888

Reload Tor, then read the generated onion hostname:

$ rcctl reload tor
$ doas cat /var/tor/searx_hidden_service/hostname

output: example.onion

Open the resulting .onion address in Tor Browser.

Run under rc.d with Gunicorn

Gunicorn serves SearXNG on localhost. A short OpenBSD rc.d script delegates process management, privilege dropping, status checks, and logging to rc.subr.

$ doas -u _searxng /bin/ksh -c 'cd /home/searxng && exec /bin/ksh -l'

$ pip install gunicorn
(...)
Successfully installed gunicorn-26.0.0
$ nano searxng.conf.py

# Server Socket ========================================================
bind = "127.0.0.1:8888"
backlog = 128

# Worker Processes =====================================================
workers = 1
keepalive = 5
worker_class = "gthread"
threads = 4
timeout = 120
graceful_timeout = 30

# Process Naming =======================================================
proc_name = "searxng"

# Config File ==========================================================
wsgi_app = "searx.webapp:application"

# Server Mechanics =====================================================
chdir = "/home/searxng/src"
raw_env = [
    "PYTHONPATH=/home/searxng/src",
    "SEARXNG_SETTINGS_PATH=/home/searxng/settings.yml",
]

# Logging ==============================================================
accesslog = "-"
errorlog = "-"

Create the service script:

$ nano /etc/rc.d/searxng

#!/bin/ksh
daemon="/home/searxng/pyenv/bin/gunicorn"
daemon_user="_searxng"
daemon_execdir="/home/searxng/src"
daemon_flags="-c /home/searxng/searxng.conf.py"
daemon_logger="daemon.info"

. /etc/rc.d/rc.subr

rc_bg=YES
rc_reload=NO

rc_cmd "$1"
$ chown root:wheel /etc/rc.d/searxng
$ chmod 0555 /etc/rc.d/searxng
$ rcctl enable searxng
$ rcctl start searxng
searxng(ok)

Updating SearXNG

This installation tracks SearXNG's master branch. Read the upstream update and migration documentation before running this helper. The git reset --hard command deliberately discards local changes in the source checkout; the separate settings.yml remains untouched.

$ doas -u _searxng nano ~_searxng/update.sh

#!/bin/ksh
set -eu

cd /home/searxng/src
git fetch --prune origin
git reset --hard origin/master
/home/searxng/pyenv/bin/python -m pip install --upgrade pip setuptools wheel
/home/searxng/pyenv/bin/python -m pip install --upgrade gunicorn
/home/searxng/pyenv/bin/python -m pip install \
  --use-pep517 --no-build-isolation --upgrade --editable .
$ chmod 0750 ~_searxng/update.sh

To upgrade:

$ doas -u _searxng /bin/ksh /home/searxng/update.sh
$ diff -u ~_searxng/src/searx/settings.yml ~_searxng/settings.yml

$ rcctl restart searxng
searxng(ok)
searxng(ok)

Conclusion

This onion-only setup does not require an Internet-facing reverse proxy or public TLS certificate. Tor onion services authenticate the onion address and encrypt traffic between the client and the service; Gunicorn listens only on the loopback interface. This removes the public HTTP and TLS components that a clearnet deployment would need.

If you choose to expose SearXNG on clearnet instead, you should still configure HTTPS correctly.
